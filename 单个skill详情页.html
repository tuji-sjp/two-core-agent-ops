概述

GitHub Skill 是一个强大的 AI 代理技能，它封装了 GitHub CLI (gh) 的核心功能，让你能够通过自然语言与 GitHub 进行交互。无需记忆复杂的命令语法，只需描述你想要完成的任务，AI 代理就会自动生成并执行相应的 gh 命令。

该技能原生处理身份验证、分页和结构化输出，支持所有主流的 GitHub 操作，包括但不限于：

  • 拉取请求(PR)的创建、查看、审查和合并
  • 议题(Issue)的创建、分配、标签和关闭
  • CI/CD 工作流的监控和调试
  • 发布(Release)的管理
  • 代码审查流程的自动化
  • 仓库元数据的查询和更新

✅ 适用场景

  • 当你需要快速查看 PR 的 CI 状态和审查意见时
  • 当你想要批量管理多个 Issue 或 PR 时
  • 当你需要调试失败的 CI 工作流并查看详细日志时
  • 当你想要自动化发布流程时
  • 当你需要获取 GitHub API 中没有直接对应命令的高级数据时

❌ 不适用场景

  • 你的代码仓库托管在非 GitHub 平台(如 GitLab、Gitea、Bitbucket)
  • 操作需要 GitHub 管理员权限而当前用户没有
  • 需要直接修改 Git 历史记录或执行复杂的 Git 操作(请使用 Git Skill)

📦 底层依赖

  • GitHub CLI (gh) >= 2.0.0
  • Bash 或 Zsh 终端环境

安装与配置

前置条件

  1. 已安装 GitHub CLI (gh) 并完成身份验证
  2. 已安装 Node.js >= 18.0.0
  3. 已安装并配置好你的 AI 代理平台

方式一：自动安装(推荐)

方式二：通过 SkillHub 安装

方式三：手动安装

  1. 下载技能 ZIP 文件并解压
  2. 将解压后的文件夹复制到你的 AI 代理技能目录
  3. 重启你的 AI 代理服务

环境配置

本技能不需要额外的环境变量配置，它会自动使用 gh CLI 的身份验证信息。

如果你还没有登录 GitHub CLI，请先运行： 

gh auth login

按照提示完成身份验证流程。

常见用例

1. 拉取请求(PR)管理

查看 PR 的 CI 状态
gh pr checks 55 --repo owner/repo
列出所有打开的 PR
gh pr list --state open --repo owner/repo
创建一个新的 PR
gh pr create --title "feat: 添加用户认证功能" --body "这是一个实现用户认证功能的PR" --base main --head feature/user-auth --repo owner/repo
合并一个 PR
gh pr merge 55 --squash --repo owner/repo

2. CI/CD 工作流监控

列出最近的工作流运行
gh run list --repo owner/repo --limit 10
查看工作流运行详情
gh run view  --repo owner/repo
只查看失败步骤的日志
gh run view  --repo owner/repo --log-failed
重新运行失败的工作流
gh run rerun  --repo owner/repo

3. 议题(Issue)管理

列出所有打开的 Issue
gh issue list --state open --repo owner/repo
创建一个新的 Issue
gh issue create --title "bug: 登录页面崩溃" --body "当用户输入错误密码时，登录页面会崩溃" --label "bug" --repo owner/repo
关闭一个 Issue
gh issue close 123 --repo owner/repo

4. 高级 API 查询

对于 gh 子命令不直接支持的操作，可以使用 gh api 直接调用 GitHub REST API。

获取 PR 的特定字段
gh api repos/owner/repo/pulls/55 --jq '.title, .state, .user.login'
获取仓库的贡献者列表
gh api repos/owner/repo/contributors --jq '.[].login'
获取指定标签的所有 Issue
gh api repos/owner/repo/issues --jq '.[] | select(.labels[].name == "bug") | "\(.number): \(.title)"'

5. 结构化输出与过滤

大多数 gh 命令都支持 --json 参数来获取结构化输出，结合 --jq 参数可以轻松过滤和格式化结果。

列出 Issue 编号和标题
gh issue list --repo owner/repo --json number,title --jq '.[] | "\(.number): \(.title)"'
统计每个状态的 PR 数量
gh pr list --repo owner/repo --json state --jq 'group_by(.state) | map({state: .[0].state, count: length})'

API参考

核心命令

命令 功能描述 常用参数
gh pr <subcommand> 管理拉取请求 view, list, create, merge, checks, review
gh issue <subcommand> 管理议题 view, list, create, close, label, assign
gh run <subcommand> 管理 GitHub Actions 运行 list, view, rerun, cancel, watch
gh release <subcommand> 管理发布 create, list, view, delete, upload
gh api <endpoint> 直接调用 GitHub API --jq, --method, --field
gh repo <subcommand> 管理仓库 view, clone, fork, create

全局参数

参数 描述
--repo <owner/repo> 指定要操作的仓库(当不在 git 目录中时必须使用)
--json <fields> 以 JSON 格式输出指定字段
--jq <filter> 使用 jq 表达式过滤 JSON 输出
--limit <number> 限制返回结果的数量
--state <state> 按状态过滤结果(open, closed, all)

错误码及解决方案

错误码 描述 解决方案
authentication failed GitHub 身份验证失败 运行 gh auth login 重新登录
repository not found 仓库不存在或没有访问权限 检查仓库地址是否正确，确认你有访问权限
pull request not found PR 不存在 检查 PR 编号是否正确

command not found: gh GitHub CLI 未安装 安装 GitHub CLI 并添加到 PATH

最佳实践

1. 始终指定仓库

当你不在 git 目录中时，务必使用 --repo owner/repo 参数指定要操作的仓库，避免操作错误的仓库。

2. 使用结构化输出

尽可能使用 --json 和 --jq 参数来获取和处理数据，这样可以获得更准确、更易于解析的结果。

3. 限制结果数量

使用 --limit 参数限制返回结果的数量，特别是在大型仓库中，可以显著提高命令执行速度。

4. 批量操作

对于需要处理多个资源的任务，优先使用支持批量操作的命令，而不是多次调用单个命令。

5. 安全注意事项

  • 不要在公共场合分享你的 GitHub 个人访问令牌
  • 定期审查和撤销不再需要的访问令牌
  • 对于敏感操作，先在测试仓库中验证命令的正确性

6. 性能优化

  • 只请求你需要的字段，避免获取不必要的数据
  • 使用缓存来存储不经常变化的数据
  • 对于大型查询，考虑使用分页来减少单次请求的数据量

7. 常见陷阱

  • 注意 PR 和 Issue 编号的区别，不要混淆
  • gh pr merge 默认使用合并提交，如果你想要压缩提交或变基，需要明确指定 --squash 或 --rebase 参数
  • gh api 默认使用 GET 方法，如果你需要执行 POST、PUT 或 DELETE 操作，需要使用 --method 参数指定

常见问题

Q: 我如何在多个 GitHub 账户之间切换？

A: 你可以使用 gh auth switch 命令在已登录的多个账户之间切换。

Q: 我可以使用这个技能来管理 GitHub Enterprise 仓库吗？

A: 是的，只要你已经使用 gh auth login --hostname <your-enterprise-hostname> 登录到你的 GitHub Enterprise 实例。

Q: 这个技能支持 GitHub GraphQL API 吗？

A: 是的，你可以使用 gh api graphql 命令来调用 GitHub GraphQL API。

Q: 我如何查看命令的完整帮助信息？

A: 你可以在任何命令后添加 --help 参数来查看详细的帮助信息，例如 gh pr create --help。

Q: 这个技能可以自动审查代码吗？

A: 这个技能本身不提供代码审查功能，但它可以与其他代码审查技能结合使用，自动获取 PR 的代码变更并提交给代码审查技能进行分析。
